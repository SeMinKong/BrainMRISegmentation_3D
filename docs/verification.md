## 재실행

프로젝트 루트에서:

```powershell
.\.venv\Scripts\python.exe -E -m pytest
.\.venv\Scripts\python.exe -E -m ml.smoke --output runs/smoke
Push-Location frontend
npm.cmd run build
Pop-Location
```

실제 환자 데이터의 성능, CUDA 학습, 학습된 nnU-Net 가중치 추론, DICOM 입력은 이번 검증에 포함하지 않았습니다. 웹 지표는 해당 마스크에 대한 측정값이며 임상 정확도 검증을 뜻하지 않습니다.

## 추론 조회 안정화 검증 — 2026-09-08

통신 실패를 추론 실패로 표시하던 문제와 사례 전환 후 이전 응답이 선택값을 덮을 수 있던 문제를 수정했습니다. 완료 결과 조회의 재시도, 요청 취소, 404 이후 작업·사례 재동기화도 포함합니다.

| Chrome에서 작업 404 → 작업·결과 다시 연결 → 작업 목록 갱신과 새 실행 가능 상태 복구 | 통과 |

브라우저 검증은 실제 프로덕션 React 빌드에 합성 API 응답을 주입해 수행했습니다. 수정 전 빌드에서는 첫 번째 503 이후 비교 화면으로 복구하지 못하는 문제를 재현했습니다. 실제 환자 데이터나 학습된 모델을 실행한 검증은 아닙니다.

추가된 회귀 테스트는 신규 패키지 설치 없이 다음 명령으로 실행합니다.

```powershell
npm.cmd --prefix frontend test
```

이 환경에서는 기존 `.pytest_cache` 임시 폴더 접근이 제한되어 캐시 플러그인을 끄고 `runs/` 아래의 새 임시 경로로 Python 테스트를 실행했습니다. Vite 빌드는 샌드박스의 상위 폴더 읽기 제한을 해제한 실행에서 통과했습니다. 소스 수정으로 우회한 것은 아닙니다. Python 테스트에는 기존 Starlette/AnyIO 사용 중단 예정 경고 두 건이 남아 있습니다.

## MU-Glioma-Post 기준 정리 검증 — 2026-09-08

README·문서·UI·기본 프리셋·모델 라벨 계약·manifest 예제를 MU-Glioma-Post 기준으로 정리했습니다. 데이터 다운로드 출처는 [MU-Glioma-Post 공식 페이지](https://www.cancerimagingarchive.net/collection/mu-glioma-post/)만 사용합니다.

- 백엔드·ML 테스트 **34개 통과**: 기본 프리셋, 라벨 의미를 확인한 저장 사례 호환 처리, 원본 파일 비변경, generic 사례 추론 거절, 명시적 환자 정규식, 두 파일명 구분자와 동일 환자의 검사 분할을 포함합니다.
- 프런트엔드 회귀 테스트 **16개 통과**, TypeScript·Vite 빌드 통과.
- Chrome에서 가져오기 기본 프리셋 `mu_glioma_post`, MU-Glioma-Post 데이터 링크와 사용 가능한 선택 항목을 확인했습니다.
- 같은 빌드에서 통신·완료 결과 조회의 자동 복구, 사례 전환 중 늦은 응답 무시, 404 이후 다시 연결을 재확인했습니다.

브라우저 검증에는 합성 API 응답을 사용했습니다. 실제 다운로드 파일과 MU-Glioma-Post 학습 성능은 아직 검증하지 않았습니다. 저장된 사례는 라벨 의미를 기준으로 읽을 때만 정규화하며, 이번 변경 과정에서 사용자 NIfTI나 사례 파일을 다시 쓰지 않았습니다.

## 실제 다운로드 파일 점검 — 2026-09-10

로컬 `data/MU-Glioma-Post`의 203개 환자 ID·596개 검사·2,978개 NIfTI를 전수 확인했습니다. 모든 파일의 gzip CRC, 복셀 유한성, 허용 라벨, 사례 내 shape·affine 일치를 통과했습니다. 전체 볼륨은 240×240×155, 1 mm, LPS 방향이며 웹에서 RAS로 정규화할 수 있습니다. 이 검사는 파일 형식·무결성·좌표 호환성에 대한 것으로 모델 성능이나 주석 정확도 검증은 아닙니다.

마스크가 없는 2개 검사를 별도 목록에 기록했습니다. 서로 다른 환자 ID에서 MRI 4종이 동일한 11쌍(22개 검사), 같은 검사에서 T1과 FLAIR 파일이 동일한 1개 검사는 지도 학습 목록에서 제외했습니다. 11쌍 중 3쌍의 마스크는 동일하며 8쌍은 실제 복셀 값이 다름을 확인했습니다. 원인을 추정해 파일이나 라벨을 수정하지 않았습니다.

원본을 보존한 기본 manifest는 571개 검사·200개 환자 ID입니다. 학습 435개/검증 136개로 나누고, 동일 파일로 연결된 환자 ID는 남은 검사도 같은 분할 그룹에 넣었습니다. 분할 간 환자 ID 교차와 확인된 파일 내용 중복은 없습니다. 생성 스크립트의 seed 42 분할 재현과 원본 경로·파일 크기·수정 시각 보존을 독립적으로 확인했습니다.

- 실제 `*_brain_*` MRI 4개와 `*_tumorMask` 1개를 임시 API 저장소에 가져오기: 통과.
- 4개 시퀀스의 축상 단면, 관상·시상 단면, 3D mesh 응답: 통과.
- 다운로드한 마스크와 RAS 정규화된 원본의 복셀 값·affine 완전 일치: 통과.
- 원본 파일명을 지원하는 백엔드·manifest 회귀 테스트를 포함한 Python 테스트: 43개 통과.

상세 파일·제외 목록과 결과는 Git에서 제외되는 `data/quality-check/`에 저장했습니다. 첫 사례의 영상과 원래 주석을 사용한 검사이며 학습 또는 모델 추론은 실행하지 않았습니다.
